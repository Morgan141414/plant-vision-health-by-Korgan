# Локальная классификация видов

`PlantClassifier` — адаптер для **предварительно валидированной локальной**
TorchScript-модели. По умолчанию он не загружает модели, не делает сетевых
запросов и возвращает `unavailable`. Это важно: CLIP/torchvision с общими
весами нельзя честно выдавать за определитель городских растений, особенно для
критичных решений о здоровье дерева.

## Подключение после валидации

1. Установить ML extras: `pip install -e '.[ml]'`.
2. Подготовить локальный TorchScript-файл, например `models/species.pt`, и
   `models/species_labels.txt` с одной меткой на строку. Порядок должен
   соответствовать выходу модели. В первую очередь включить подтверждённые
   локальные классы (`карагач`, `тополь`, `берёза`, хвойные и т. п.).
3. В точке интеграции создать `PlantClassifier(model_path, labels_path)` и
   передать OpenCV BGR-кадр в `classify`. Результат сериализуется через
   `to_dict()`.

На M4 `device="auto"` выбирает MPS, иначе CPU. Для deployment стоит отдельно
измерить latency и память на целевом 1080p-пайплайне; этот модуль не заявляет
достижение 60 FPS или порогов ТЗ.

## Почему не CLIP по умолчанию

Zero-shot CLIP без локальной калибровки создаёт правдоподобные, но ненадёжные
видовые ответы. Его можно использовать только как отдельный исследовательский
режим с зафиксированными локальными весами, закрытым перечнем классов,
отложенной выборкой и порогом отказа — не вместо данной production-точки.
