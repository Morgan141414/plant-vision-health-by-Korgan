# PlantVision AI

Исследовательский прототип локального сервиса компьютерного зрения для наблюдения за городской растительностью с БПЛА и наземных камер.

## Что уже работает

- FastAPI API и веб-интерфейс для загрузки фотографии;
- детерминированная демо-оценка растительного покрова по зелёным пикселям;
- JSON-ответ с границами зоны растительности, покрытием и безопасным статусом `REQUIRES_REVIEW`;
- готовая точка подключения для production-модели сегментации.

Демо-режим **не идентифицирует вид и не ставит диагноз**. Он специально не имитирует клиническую или дендрологическую точность: здоровье и вид возвращаются как `unavailable` до подключения валидированных моделей и датасета.

## Быстрый запуск

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
uvicorn app.main:app --reload
```

Откройте `http://127.0.0.1:8000`. Документация API доступна на `/docs`.

## Контракт API

`POST /api/v1/analyze` принимает `multipart/form-data` с полем `image` и возвращает:

```json
{
  "mode": "demo_vegetation_mask",
  "plant": {"name": "unavailable", "confidence": null},
  "health": {"status": "REQUIRES_REVIEW", "confidence": null},
  "vegetation": {"coverage_percent": 0.0, "bbox": [0, 0, 0, 0]},
  "disclaimer": "..."
}
```

## Путь к целевой системе

1. Разметить независимый COCO-набор: лист, ветка, ствол, цветок/бутон, фон.
2. Обучить и валидировать instance-segmentation отдельно от классификации вида и признаков состояния.
3. Подключить реализацию `SegmentationEngine` с YOLO-seg / ONNX / Core ML и измерить latency, память и метрики на M4.
4. Включать статусы здоровья только после экспертной валидации. Система должна сохранять вариант «не определено / нужен осмотр».

Целевые пороги из ТЗ являются критериями приёмки, а не заявленными результатами этой версии.
